# Handoff — 2026-10-09/10

Rodrigo asked for four features (notifications, floating voice controls, an Accounts page with an
`.env` manager, visualization upgrades). Work ran in parallel git worktrees, one agent per feature,
each reviewed by a separate read-only agent, then merged on `feat/integration`, fast-forwarded to
`local`, deployed to the Jetson and the POCO, and checked by hand. Two security holes and the
context-sync problems were found and fixed along the way. Everything below is on `local` and pushed.

## 1. Notifications when an agent session finishes

- **Backend:** `SessionPool.send()` (`backend/api/pool.py`) emits `agent_turn_started` and
  `agent_turn_finished {session_id, sdk_session_id, provider, title, status ok|error|interrupted,
  preview, error}` to every orchestrator socket (spec 12 §3.7, TURN-1/TURN-2). Both are
  non-blocking; a turn cancelled between an abandoned attempt and its retry is announced
  `interrupted` (`pool.announce_turn_aborted`). Tests: `backend/tests/test_pool_turn_watcher_events.py`.
- **Web:** `src/app/notifications/` (`turnNotices.ts` decision, `turnNotifier.ts`, lazy `start.ts`
  that buffers frames until the chunk loads, `viewPresence.ts` so a second tab doesn't notify while
  another shows the session), `src/platform/notifications.ts` (service worker first, page fallback),
  `public-main/sw.js` `notificationclick`. Settings → Notifications (`notifyAgentTurns`, off by
  default; needs HTTPS; hidden/explained on Safari 12). Console markers `[notify] …`.
- **Android main app:** `app-main/.../system/TurnNotifier.kt` (`TurnAttention`, `AgentWork`,
  `SystemTurnSink`; channel `agent_turns`, importance HIGH, id 1004, tag `turn:<localId>`),
  Settings → This device → **Notifications**. While a turn runs and the switch is on, the voice-host
  foreground service is held ("Waiting for N agent sessions", special-use type, never the mic type).
  Log tag `ArchieNotify`.
- **Fixed on 2026-10-10 after Rodrigo asked where it was:** the Notifications page was never listed on
  the Android Settings home (unreachable) — added, with
  `SettingsUiTest.home_listsEveryDevicePage_includingNotifications`; and "looking at it" followed the
  process lifecycle (ON_STOP ~1 s late), so a turn finishing right after Home was suppressed — it
  now follows `MainActivity` `onResume`/`onPause` (`7fd6e99`). **Verified on the POCO:** a real
  system notification in the shade and on the lock screen.
- **Limit:** frames arrive only while the app runs. A turn started on the phone is covered after
  pocketing it; turns started elsewhere while Archie is closed need "Stay connected in background".
  No Web Push / FCM server.

## 2. Floating voice controls

While this device has a voice call and the visible view is not the Archie conversation, the same
controls float over every page: above the rail and list pane, under the compact drawer, dialogs and
sheets (Rodrigo chose this). After 4 s idle they shrink to a 0.55-opacity pill that still shows the
mic state; any pointer, touch, wheel or key wakes them, including inside same-origin visualization
iframes (re-scanned via a MutationObserver); the first tap on the pill only wakes it. Drag snaps to six
anchors, saved per device (`voiceOverlayAnchor`). Web: `features/voice/{VoiceOverlay.tsx,
useActivityIdle.ts, overlay.ts, lazyOverlay.tsx}`, `app/shell/VoiceOverlayHost.tsx`. Android:
`feature/chat` `VoiceDockModel` (one process-wide reconnect timeline shared by the dock and the
overlay), `ui/VoiceOverlay.kt`, `app-main/.../shell/VoiceOverlayHost.kt`. Gallery:
`#/dev/gallery/voice?screen=overlay&state=listening` (dev server only). Detail:
[voice/architecture.md](../voice/architecture.md) "Floating voice controls". Not yet tried in a real
call.

## 3. Settings → Accounts and the `.env` manager

Every service with every method it supports (research and per-CLI behaviour:
[harnesses/authentication.md](../harnesses/authentication.md)). Backend `backend/manager/accounts/`
(registry, `flows.py` PTY/pipe login driver, `envfile.py`), routes `/api/accounts/*` and `/api/env/*`
(spec 12 §8.1, ACC-1..4); web `features/settings/accounts/`; Android `AccountsModel.kt` +
`ui/AccountsPage.kt`. The first-run AuthGate's "Sign in with Claude" now uses the link flow.

**The lesson:** `codex login` and `claude auth login` delete or empty the existing credentials
**when they start**. Logins therefore run in a temporary home and the result is copied in only on
success; the driver also snapshots the credential files and restores them on any other outcome. A
probe on 2026-10-09 (before that fix) wiped the laptop's `~/.codex-archie/auth.json` — the laptop
needs one Codex device-code sign-in. `.env` edits keep only the touched lines, back up to
`<repo>/.backups/env/` (0700/0600, gitignored, not synced) and force `context/.env` to 0600.

## 4. Visualizations: live reload, in-app links, the canvas skill

- `backend/api/content_watcher.py` (one watchfiles loop over `context/public/`, `context/memory/`
  and `docs/`; 300 ms coalescing; polling fallback; restarts on errors) pushes
  `visualization_changed` / `memory_changed` (spec 12 §9.3) and wakes the memory indexer. Public and
  `/memory/` files are served with `no-cache` + ETag/304; `/<dir>/` serves `index.html`; unknown
  `*.html` is 404, not the app shell.
- Open visuals reload (scroll kept; deferred while hidden), memory docs refetch, an "Updated" cue;
  reconnect catch-up.
- Links (spec 12 §9.4, LNK-1..7): one resolver per platform (`apps/web/src/features/links/`,
  Android `:core:markdown` `InternalLinks.kt`) sharing `apps/protocol-fixtures/links/internal-links.json`.
  Convention for agents: root-relative markdown links `[T](/<project>/)`, `[T](/memory/<path>.md)`.
  A visual opens in the viewer only if it is in the list (after one refresh); otherwise "Open in browser".
- `context/skills/create-viz/` rewritten as an "interactive canvas" skill (lean `SKILL.md` +
  `references/patterns.md`, `references/devices.md`); AGENTS.md, MEMORY.md and ORCHESTRATOR_MEMORY.md
  carry the link convention.

## 5. Security

- **File read through the SPA catch-all (critical, live on the Jetson):** `GET //etc/hostname` (or
  any path, `context/.env` included) was served. Fixed in `683c4f4` (resolve + stay inside the
  dist), deployed the same hour; regression test `backend/tests/test_spa_root_traversal.py`. The new
  folder-index code got the same guard.
- **Cross-site requests:** CORS answered `*` and nothing checked Origin or Host, so any web page could
  read history or send prompts to agents. `backend/api/guard.py`: `RequestGuardMiddleware` (writes
  and WebSocket handshakes; Host check on all `/api/*` plus `/memory`, `/uploads`, `/projects`) and
  `TrustedCORSMiddleware`. Static pages stay reachable from any device by IP. Overrides:
  `ARCHIE_TRUSTED_ORIGINS`, `ARCHIE_TRUSTED_HOSTS`. Detail:
  [backend.md](../architecture/backend.md#auth-and-the-browser-origin-guard).
- The browser-extension daemon's `POST /api/uploads` got the guard too.

## 6. context-sync rework

Causes found: a VS Code instance (a large JS project window) held ~51k of the laptop's 65,536 inotify
watches, so `inotifywait` silently stopped watching five new `context/` directories; and a
bidirectional echo race resurrected deleted files. Now (`e619bd2`, `1c306a3`, `8f7f461`, `faa2382`):

- laptop `fs.inotify.max_user_watches=524288` (`/etc/sysctl.d/60-inotify.conf`); global VS Code
  `files.watcherExclude`;
- the script restarts itself when a directory can't be watched; no `rsync --delete` anywhere; live
  pushes send only the changed paths;
- tombstones (2 min, both sides) stop deleted files coming back and the delete ping-pong;
- a **manifest** (last agreed state) + **reconcile** (startup, after an outage, every 10 min) replays
  deletes made while apart; an edit beats a delete;
- every removal goes to `context/.sync-trash/<date>/` (30 days);
- the **brake**: more than 50 deletions at once or 25 % of the files are held —
  `infra/sync/context-sync.sh --status | --approve-deletes | --reject-deletes`.

Tests: `infra/sync/test/run-suite.sh` (two local instances, fake ssh with an offline switch, 17
checks, ~5 min; also run on the Jetson). Detail: [context-sync.md](../infrastructure/context-sync.md).

## 7. How the work was run (reusable)

- **Worktrees** under `~/assistant-wt/<name>` (branch per feature), with `.venv`, `context`,
  `apps/web/node_modules`, `apps/design-tokens/node_modules` symlinked from the main tree,
  `assistant_config.json` and `apps/android/{local,keystore}.properties` copied, and those symlinks
  added to `info/exclude`. Remove the symlinks with guarded paths before `git worktree remove`.
- **`shared/scripts/heavy.sh`** for every build/test (one lock, free-RAM wait, cgroup cap, capped
  Gradle). **`shared/scripts/lean_backend.py`** for hands-on tests without PyTorch.
- One read-only review agent per branch caught ~20 real bugs before merge; reviews are worth it.
- Merges between branches that both add frames/settings conflict mechanically (keep both); the web
  `initialJs` budget (190 kB) was exceeded only after merging — check budgets on the merged tree.
